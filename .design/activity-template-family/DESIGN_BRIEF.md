# Activity Template Family｜等待期设计简报

日期：2026-09-02  
状态：等待品牌团队完整 Figma 输入前的结构改造  
承接：`.design/phase-1-5/DESIGN_BRIEF.md` 与当前员工活动单海报切片

## 1. 已确认输入

- 模板按业务场景组成模板家族，不是互不相关的单张模板。
- 员工活动家族预计同时包含：
  - `1920 × 1080` 横版海报。
  - `1080 × 1920` 竖版海报。
  - `2227 × 950` 推文 Banner。
  - 宽度 `1080` 的长图推文；最终高度与自适应规则待确认。
- 同一活动的一组输出需要在视觉主题、主视觉主体、标题语义和业务事实方面保持一致。
- 模板示意图中的灰色区域表示视觉主元素的焦点区域，不是局部图片插槽。
- AI 视觉资产应作为全幅背景或背景母版使用；Logo、标题、日期、地点、CTA、二维码等仍由受控 HTML/CSS 叠加。
- 用户应填写一次活动简报并确认一次核心文案，系统再生成整组物料。

## 2. 等待完整输入前不能假定的内容

- 长图推文的精确高度、最大高度和分页/截断策略。
- 各规格的主视觉焦点区域、文本安全区、Logo 安全区和 CTA 区域。
- 四个规格是否复用同一张背景裁切，还是共享视觉母版但分别生成不同宽高比资产。
- 各规格允许出现的内容模块、内容密度和最大字数。
- 正式 Logo、字体文件、字体授权、颜色值、装饰资产和降级背景。
- 完整底图的遮罩、渐变、对比度和图文避让规则。

这些值在正式 Figma 与品牌资产到达前不得写成正式模板常量或视觉回归基线。

## 3. 目标领域模型

```text
CampaignBrief
  -> CampaignDocument
  -> VisualMaster
  -> OutputBundle
       -> landscape_poster
       -> portrait_poster
       -> article_banner
       -> longform_article
```

- `CampaignBrief`：用户一次填写的业务事实，与具体模板无关。
- `CampaignDocument`：一次生成、一次确认的主文案和结构化内容模块。
- `VisualMaster`：整组物料共享的视觉主题、主体和可追踪的视觉资产族。
- `TemplateFamily`：同一场景的一组规格变体及其共同品牌规则。
- `RenderTarget`：某个规格选择哪些内容模块，以及相应的密度、焦点区和安全区。
- `OutputBundle`：一次任务交付的整组物料。
- `Artifact`：其中一个规格的不可变输出和独立校验结果。

## 4. 背景与视觉一致性

模板元数据应声明：

- `backgroundMode: full_bleed`。
- 主元素焦点区，使用相对坐标表达，避免绑定某个像素尺寸。
- 文本安全区、Logo 安全区、CTA/二维码禁入区。
- 背景适配策略：裁切、扩图或同视觉母版的规格派生。
- 降级背景和最小对比度策略。

一致性不等于四张图使用完全相同的像素裁切。系统需要锁定同一个 `visualFamilyId`、主题、主体、调色板和风格，并允许为不同宽高比生成或派生匹配资产。

## 5. 产品流程

```text
选择业务场景
  -> 一屏填写活动简报
  -> 查看系统推荐的物料组合
  -> 生成并确认主文案
  -> 生成统一视觉母版
  -> 并行渲染各规格
  -> 按规格预览、重试或下载整组
```

首页不再要求用户先理解模板或逐个选择尺寸。员工活动默认勾选四项物料；高级选项允许取消某项，但不要求用户从空白组合开始。

## 6. 等待期成功标准

- 领域契约不再把任务锁定为单一 `1080 × 1920` 输出。
- 当前临时模板可以作为一个草稿模板家族运行，但不冒充正式品牌模板。
- 同一活动只生成和确认一次核心文案。
- 任务可以包含多个 Artifact，并支持单项失败、单项重试和整组完成状态。
- 表单压缩为一屏核心信息；高级信息按需展开。
- UI 能预览一个物料组合，即使正式视觉仍使用占位模板。
- 正式 Figma 到达后，只需填写模板元数据并实现各规格 renderer，无需重写任务和表单模型。
