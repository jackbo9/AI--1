## 结论

T01 的几何、字体和信息结构已经接近 Figma，但还不能作为稳定模板完成验收。主要问题是背景生成、文字颜色、Logo 版本和遮罩之间没有确定性适配：当前模板固定使用深色文字，背景安全区一旦出现人物、地毯、草地或落叶，正文会失去稳定对比度。

这项工作对应模板家族计划中的 C3“确定性图文适配”，同时需要提前实现一小部分 E1 对比度发布门。应暂停 B3/B4，先把 C3 拆成只服务 T01 的纵向切片。

## Must Fix

1. **正文区域没有图文适配**：当前 sessions、audience、participation 固定使用 `#1C1C1E` / `#48484A`，且背景与文字之间没有处理层。第一、二组文字落在高纹理和多色交界上。
2. **校验不检查视觉对比度**：渲染后只校验业务字段是否被改写，随后 Artifact 直接进入 READY；无法阻止低可读性成品。
3. **全局明暗主题不足以解决本图**：顶部是浅色净空，第一、二组位于繁杂中间色，第三组和页脚又回到浅色。同一张图必须按区域处理，不能整张统一换成白字或黑字。
4. **Logo 版本尚未参与背景适配**：公司 Logo 只有固定版本；遇到深色或繁杂顶部背景时没有受控反白资产或失败策略。

## 实测提示

对合成前背景按最终 cover 几何采样，并以 4.5:1 检查正文候选色：

- 标题区域深色正文通过像素约 100%。
- 时间/地点区域 `#48484A` 通过像素约 74.4%。
- 参与对象区域 `#48484A` 通过像素约 82.1%。
- 参与方式和页脚区域深色正文通过像素约 100%。

这里的百分比用于定位风险，不直接充当最终 WCAG 证明。它说明问题集中在局部区域，白字在这些中亮背景上反而更差，应优先尝试局部浅色柔性遮罩，而不是全局反白。

## 建议的新执行顺序

```text
B2 几何对齐（当前）
  -> C3a T01 背景区域分析
  -> C3b T01 受控文字/Logo/遮罩选择
  -> E1a T01 对比度发布门
  -> E2a T01 多背景视觉回归与人工验收
  -> 再开始 B3/B4 其他规格
```

## C3a：背景区域分析

- 在背景按 `object-fit: cover` 完成最终裁切后、文字合成前分析；不得分析原图未裁切坐标。
- Manifest 明确声明 `header`、`title`、`sessions`、`audience`、`participation`、`qr`、`footer` 区域。
- 每个区域计算相对亮度分位数、对比度通过率和纹理/边缘密度；不要只看平均亮度。
- 分析结果写入 Artifact/GenerationVersion，保证可追踪和可复现。
- 若使用 Sharp，应把它声明为项目直接依赖，不依赖 Next.js 的传递依赖。

## C3b：受控图文处理

不要先手写一个固定全局蒙层。建立小型受控枚举，并由区域分析选择：

- `dark_text_clean`：浅色、低纹理背景；无遮罩。
- `dark_text_light_scrim`：中亮或繁杂背景；深色文字 + 局部浅色柔性遮罩。
- `light_text_dark_scrim`：深色背景；白色标题/Logo + 局部深色柔性遮罩。
- `fallback_background`：允许的最大遮罩仍不达标时使用品牌降级背景。

T01 第一版允许标题区和底部信息区选择不同 treatment。遮罩应是连续、无明显边框的局部渐变或柔性雾化层，不使用圆角卡片、阴影或重新引入旧版白色信息面板。遮罩范围应略大于文字包围盒，并通过 CSS 变量注入强度；允许档位应固定，例如 `0 / 0.12 / 0.20 / 0.28 / 0.36`，选择满足标准的最低档。

当前样张的优先修复方向：

- 顶部保持深色文字、无遮罩。
- 在约 `y=1310–1590` 建立浅色渐变过渡，使时间/地点和参与对象达到对比度要求。
- `y=1588` 以下原图已接近浅色净空，不应为了前两组正文给整张底部套统一高强度遮罩。

## E1a：T01 发布门

- 22 px Regular 正文、18 px 页脚和二维码说明按 4.5:1 检查。
- 28 px Semibold 分组标题和 120 px 标题按至少 3:1 检查。
- 检查应针对最差分位或区域通过率，不以平均对比度放行。
- 遮罩合成后重新计算；仍不通过则切换 treatment、使用降级背景或阻止该 Artifact 下载。
- `validation.passed=false` 的 Artifact 不得进入可下载 READY 状态。

## Prompt 的职责

继续要求 Seedream 避让文字安全区并减少高频细节，但 Prompt 只是提高成功率：

- 图片模型不得生成文字、Logo、二维码或“画出来的蒙层”。
- 不依赖“保持干净”保证可读性，因为生成结果是随机的。
- CSS treatment 和 Validator 才是最终确定性保证。

## 验收矩阵

至少准备以下真实或固定背景：

1. 浅色低纹理背景。
2. 深色低纹理背景。
3. 当前秋日样张这种局部高纹理、多颜色背景。
4. 标题区浅、正文区深的混合背景。
5. 标题区深、正文区浅的混合背景。
6. 最大遮罩仍不能达标的失败背景。
7. 默认降级背景。

每张都验证 treatment 选择、文字/Logo 版本、遮罩档位、区域对比度、Artifact 状态以及重复渲染的确定性。

## 暂缓

- B3 横版和 Banner。
- B4 长图。
- 四规格的完整 C2 派生。
- 用户可见的主题选择器或自由遮罩控制。

等 T01 在上述背景矩阵中稳定通过，再把同一 image-treatment contract 扩展到其他 RenderTarget。
