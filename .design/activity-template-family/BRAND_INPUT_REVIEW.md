# 员工活动模板家族：品牌输入审阅

日期：2026-09-03  
范围：M1 设计规范、设计基础、T01 员工活动/赛事模板、会议转写、当前 `codex/slice-demo` 实现

## 结论

员工活动可以作为 M1 主场景，并暂时统一使用一套“赛事/活动招募”母版。不同活动不新增自由模板，而是通过场景字段、可选模块、视觉主题和输出规格投影来适配。

正确的运行时边界仍是：LLM 只生成结构化内容和受控视觉 Brief；图片模型只生成无文字全幅背景；代码选择模板、主题模式和遮罩策略；HTML/CSS 完成排版；Validator 决定能否批准和导出。AI 不直接填写或修改 HTML。

当前材料已经足以开始正式模板切片，但还不能直接作为唯一运行时真源。PDF、Foundation 和导出的 SVG 之间存在几处冲突，必须先形成一个经过品牌方确认、可版本化的 `BrandSpec v1`。

## 已确认的产品与模板边界

- 一级场景：员工活动。
- M1 母版：一套赛事/活动招募母版，覆盖节日活动、竞赛、俱乐部、差旅活动等；差异由模块显隐和内容投影吸收。
- 线上输出家族：`1920x1080` 横版、`1080x1920` 竖版、`2227x950` Banner、宽度 `1080` 的自适应长图。
- 背景模式：全幅背景。图中的灰色区域表示主视觉焦点区，不是局部图片插槽。
- 同一活动只填写、生成和确认一次核心内容；各输出规格共享同一事实快照和视觉母题。
- Banner 只承载主题与关键时间信息；完整规则进入长图或推文正文。
- Logo、正文、日期、地点、CTA 和二维码由模板绘制，不进入图片模型。

## 需要品牌方裁决的规范冲突

1. **双 Logo 左右位置**：M1 Framework 写“行政黄 Logo 左上、公司 Logo 右上”；Design Foundations 和四份模板均为“公司 Logo 左上、行政 Logo 右上”。建议以 Foundation/模板为准。
2. **行政黄色值**：Framework 写 `#FAE24C`；模板 SVG 实际使用 `#FFE102`。必须确定唯一 Token，并确认行政 Logo 是否只使用原始资产色。
3. **安全边距**：Framework 的 1080 基准写 `64px`；Foundation 写竖版/长图 `72px`、横版 `96px`；现有横版和 Banner SVG 的 Logo 起点仍是 `72px`。需按每个 RenderTarget 给出最终值。
4. **标题层级**：Framework 写 H1 `64-88px`、最多 2 行；Foundation 写 H0 `120px`、H1 `80px`、建议 1-3 行。需要把 H0/H1 的使用场景、最大行数和降级顺序写入模板契约。
5. **长图高度**：规范要求 `1080 x Auto`，当前导出稿是 `1080x3000`。应把 3000 视为示例或最小基线，而不是固定最终高度。
6. **生成单位**：流程图表现为“选择尺寸”，会议共识是员工活动通常需要同一视觉的一组四规格。建议默认生成物料包，尺寸取消选择放在高级设置。

## 当前实现与正式输入的主要差距

- 当前模板使用 PingFang、海军蓝/米色/橙色和单一公司 Logo；正式规范要求 MiSans、双 Logo、品牌黑白与活动红色体系。
- 当前图片只占局部 Hero；正式模板要求全幅背景，并在不同明暗背景下切换公司 Logo、文字颜色和遮罩。
- 当前模板仅支持 `1080x1920`；领域输入也把单一输出格式写死，没有 Campaign/OutputBundle 语义。
- 当前图片生成结果为方形资产，再由局部 Hero 裁切；它没有四规格焦点区、安全区和派生策略。
- 当前视觉 Brief 使用原始输入，未读取用户确认后的内容快照；默认色板也与员工活动红色不一致。
- 当前 `minFontSize` 为 24，但 CSS 内仍有 16/17/19/20px 文字；与规范的线上辅助文字不低于 18px、层级固定不一致。
- 当前二维码生成 `margin: 1`，而品牌规范要求四周静区至少 4 个码元；渲染尺寸也未形成正式可测契约。
- 当前校验只检查少量字段和长度，且失败后仍进入 `READY_FOR_REVIEW` 并允许下载；Logo、字体、颜色、几何、对比度、二维码和成图尺寸均未成为发布门。
- 导出的 SVG 已将文字转为 Path，适合测量与比对，不适合作为可维护运行时模板；正式实现仍需重建语义化 HTML/CSS 插槽。

## 品牌知识应如何进入系统

### 强制规则：不用 RAG

进入 `BrandTokens`、`TemplateFamilyManifest`、Zod Schema 和 Validator：

- Logo 资产、黑/白版本、位置、尺寸、安全区与禁用行为。
- MiSans 字体文件、允许字重、字号层级、最小字号、行高和溢出策略。
- 品牌色、场景色、每张图允许的辅助色数量。
- 画布尺寸、边距、间距阶梯、焦点区、文本区、二维码区和禁入区。
- 二维码尺寸、静区、可扫码检查。
- 下载前必须通过的十条 Brand Check。

### 生成指导：进入版本化 StylePack/Prompt

- 员工活动的视觉主题、主体、动作、氛围、活动红色倾向。
- 单一主视觉中心、人物和手部质量、标题安全区等图像生成提示。
- 不同宽高比资产共享的 `visualFamilyId`、主体和调色板。

### 参考资料：后续再考虑 RAG

当前输入体量小、规则明确，下一阶段不需要先建设 RAG。只有拿到完整 VI 长文档、大量正反案例或不同品牌线例外规则后，才把 RAG 接入 Prompt Compiler 作为“检索相关说明”的辅助；最终合规仍由确定性规则执行。

## 目标领域模型

```text
CampaignBrief
  -> ConfirmedCampaignDocument
  -> VisualMaster
  -> OutputBundle
       -> portrait_1080x1920
       -> landscape_1920x1080
       -> article_banner_2227x950
       -> longform_1080xAuto
```

每个 Artifact 独立记录模板版本、背景资产、主题模式、校验结果和输出文件；整个 Bundle 共享业务事实、已确认文案和视觉母题。

## 建议目标流程

```text
选择员工活动
  -> 选择具体活动类型/传播目的
  -> 填写必填事实
  -> 按需增加规则、报名、联系人、二维码等模块
  -> AI 生成结构化文案
  -> 用户确认可编辑内容并冻结内容版本
  -> 编译 VisualMaster 并生成无文字全幅背景
  -> 代码选择 light/dark 主题、Logo 版本和受控遮罩
  -> 并行渲染物料包
  -> 内容、品牌、技术三类校验
  -> 预览：修改文案 / 只换视觉 / 单项重试
  -> 用户批准
  -> 下载单项或整组导出
```
