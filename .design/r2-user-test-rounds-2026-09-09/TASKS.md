## Round 1 — 用户测试文案收口

**输入门槛**

- 用户补充同事建议的截图/清单，或明确同意先按代码内可见文案清单处理。

**目标**

让测试用户只看到任务、状态和下一步，不看到 Fixture、T01、模型调用、轻量预览、本地演示等实现细节。

**实施**

- [ ] 复用现有信息架构，只修改展示文案，不在本轮改变流程和状态机。
- [ ] 盘点并分类：必须删除、改为用户语言、仅开发模式可见、可保留。
- [ ] 优先修改：
  - `src/components/activity-studio/activity-studio.tsx`
  - `src/components/activity-studio/live-preview.tsx`
  - `src/components/activity-studio/studio-shell.tsx`
  - `src/components/activity-studio/steps/step-one.tsx`
  - `src/components/t01-output-gallery.tsx`
  - `src/components/activity-studio/use-activity-studio-controller.ts`
- [ ] 用户界面避免出现 `Fixture`、`T01`、`本地演示`、`不调用模型`、`轻量预览`、`HTML/CSS` 等技术表述；开发日志和非用户可见错误可以保留技术定位信息。
- [ ] 不把真实的失败、校验警告或下载限制隐藏成成功状态。

**验收路径**

- 首屏标题与身份区。
- 填写文案、生成中、选择视觉、最终下载四个主要状态。

**轻量检查与停点**

- [ ] `npm run typecheck`
- [ ] 对本轮修改文件运行 ESLint；如项目脚本只能全量运行，则执行 `npm run lint`。
- [ ] 浏览器走一遍主流程，确认没有残留的内部文案和明显布局回归。
- [ ] 确保最新版本可通过 `http://10.6.4.183:3000/` 访问，向用户说明走查路径，然后停止。

## Round 2 — 四模板字体规格与二维码约束

**输入门槛**

- 最新模板字号、字重的精确 Figma 节点或标注。
- 已确认：横版、竖版海报始终包含二维码；不实现无二维码布局分支。

**设计判断**

四种已确认模板（竖版、横版、Banner、长图）本轮只调整字体、字号、字重和行高。竖版、横版固定使用二维码布局；Banner、长图维持其既有版式，不在本轮推导新的二维码状态或信息结构。

**实施**

- [ ] 从 Figma 提取每个受影响文本角色的字号、字重、行高和槽位尺寸，形成差异表后再编码。
- [ ] 修改并复用现有模板契约：
  - `src/brand/brand-spec-v1.ts`
  - `src/contracts/brand.ts`
  - `src/templates/activity-template-family.ts`
- [ ] 修改四种最终渲染：
  - `src/templates/employee-activity.ts`
  - `src/templates/t01-portrait-layout.ts`
  - `src/templates/t01-wide.ts`
  - 必要时 `src/templates/t01-extra-renderer.ts`
- [ ] 固定竖版、横版的二维码输入与输出约束；保持既有二维码布局，且不维护无二维码布局分支。
- [ ] 保持 Banner、长图的既有布局；保持标题最多两行、允许手动换行。
- [ ] 更新对应模板版本/契约版本，避免新旧结果无法追踪。
- [ ] 新增或修改针对竖版/横版二维码必填、字号字重、标题两行的单元测试。

**验收路径**

- 竖版：带二维码一条。
- 横版：带二维码一条。
- Banner、长图：各一条代表图。
- 标题：单行、手动两行各一条。
- 信息字段：短内容、接近上限各一条。

**轻量检查与停点**

- [ ] `npm run typecheck`
- [ ] 相关 ESLint。
- [ ] 只运行模板契约、海报 Schema、相关渲染单测。
- [ ] 只生成四种模板各一张代表图并人工快速看一遍，不跑全量视觉回归。
- [ ] 刷新 3000 端口，向用户给出四种模板的走查入口，然后停止。

## Round 3 — 长图决赛名单完整纵向切片

**输入门槛**

- 新版长图精确 Figma 节点。
- 决赛名单字段和容量规则已经确认。

**目标**

从“选择长图”开始，完成表单填写、校验、任务保存/恢复、预览、最终长图渲染的完整闭环。

**实施**

- [ ] 在现有 `PosterDocument` / 请求 Schema 上扩展结构化 `finalistGroups`，不要另建只供页面使用的平行数据结构。
- [ ] 明确复用当前模板层已存在的 `finalistGroups` 形状，或在设计字段不一致时做一次受控迁移；同步更新 `src/templates/t01-template-content.ts` 的生产映射。
- [ ] 当且仅当已选择长图时，在 `src/components/activity-studio/steps/step-one.tsx` 展示决赛名单编辑器。
- [ ] 支持设计要求内的添加、删除和排序；取消勾选长图后保留用户草稿，但不要求其他尺寸渲染名单。
- [ ] 更新 `src/components/activity-studio/types.ts`、`activity-studio-model.ts`、`use-activity-studio-controller.ts`、API 请求和持久化恢复链路。
- [ ] 同步轻量预览，让名单编辑反馈即时可见。
- [ ] 按新节点修改 `src/templates/t01-longform.ts`，实现内容驱动的自适应布局。
- [ ] 移除任何通过 `slice` 静默截断组数或人数的行为；按契约选择阻止提交、明确警告或受控分页。
- [ ] 保持其他三个尺寸的输出内容和布局不变。
- [ ] 更新模板/Schema 版本和文档契约。

**验收路径**

- 未选择长图：不出现名单编辑器，原流程可用。
- 选择长图：出现名单编辑器，可录入、修改、删除并恢复。
- 最少数据、奇数人数（若允许）、接近容量上限三种名单。
- 超容量时有明确反馈，最终图不丢人名、不裁切、不无限缩小。
- 同一任务同时选长图和其他尺寸，其他尺寸不受名单影响。

**轻量检查与停点**

- [ ] `npm run typecheck`
- [ ] 相关 ESLint。
- [ ] 只运行 Poster Schema、表单模型、任务恢复和长图渲染相关单测。
- [ ] 生成三张代表性长图：最少名单、典型名单、容量边界；人工快速查看。
- [ ] 刷新 3000 端口，给出名单填写到最终长图的走查路径，然后停止。

## Round 4 — 新视觉 Prompt 接入

**输入门槛**

- 用户提供最终 Prompt 文本、适用范围及至少 2 个期望例子/反例。

**实施**

- [ ] 对比当前 Prompt Compiler 与新输入，先写差异说明；区分硬规则和风格引导。
- [ ] 字段不可改写、Logo/二维码/正文禁止进入图片模型等硬约束继续由 Schema、模板和 Validator 执行，不因新 Prompt 放宽。
- [ ] 只修改负责视觉描述/视觉资产生成的 Prompt 版本与编译逻辑，不让模型直接编辑 HTML/CSS。
- [ ] 记录 Prompt 版本，使历史生成结果可追踪。
- [ ] 固定同一组 Fixture 比较更新前后的视觉描述和生成请求；除非用户明确要求，本轮不批量调用付费图片模型。
- [ ] 为 Prompt 编译和不可改写字段补充相关单测。

**轻量检查与停点**

- [ ] `npm run typecheck`
- [ ] 相关 ESLint 和 Prompt 编译单测。
- [ ] 展示 2–3 组编译结果差异；若获准调用图片模型，只生成最小代表样本。
- [ ] 刷新 3000 端口，向用户说明视觉生成走查路径，然后停止。
