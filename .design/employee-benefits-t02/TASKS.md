## 执行方式

读取项目 AGENTS.md、README.md、HANDOFF.md、docs/ARCHITECTURE.md、docs/CONTRACTS.md 以及本目录设计简报。使用 Figma 技能读取节点325:200；中文实现使用 apply-chinese-typesetting。保留当前T01多行在途修改，先确认其验收基线，再串行完成下列任务。用户本轮要求是规划，不是立即执行这些任务；收到实施任务后再开始编码。

所有新路径为建议名称，可按仓库习惯调整。不要创建通用表单平台、额外基础设施或空Provider。每项完成后留下可演示产物及真实验证结果，不只打勾。

## 可验收切片

- [ ] **01｜T02 Fixture → HTML → PNG。** 新增福利Input/Document Schema、T02布局Manifest与renderer，以及正常、超长、缺字段Fixture。复用brand-header、MiSans、HTML转PNG机制；按Figma输出标题/副标题/双Logo/双页脚。用本地可用且来源明确的素材验证，未取得食品原图时可用合成几何图做测量测试，但不得将其称为正式食品兜底或设计达标图。建议单行标题/副标题、25px gap，生成1080×1920PNG。验收：真实字体下行数/溢出拒绝，实际间距25±1px，重要文字不裁切；与Figma母版对照。产物：T02 PNG、布局测量报告、待设计确认的容量和安全区。

- [ ] **02｜可切换的福利Fixture工作流。** 修改StudioShell的场景/页头参数和scene列表，复用fields、LoadingCard、现有CSS与四步进度；新增福利表单、文案确认、食品视觉参数与T02预览组件。只在Fixture/开发模式开放新入口，首屏显示“下午茶食品海报 · T02”。实现独立表单状态和缓存，活动与福利切换不串数据，刷新恢复对应场景。福利不显示场次、地点、对象、规则、二维码或四规格画廊；其他未支持场景仍禁用。依赖01。验收：无真实模型也能完成四步，单模板无多余选择屏，桌面及窄屏可操作；Fixture结果明确标识。

- [ ] **03｜真实福利任务创建、确认与恢复。** 修改contracts/job、创建与确认API、job-store，新增按scene判别的福利契约和服务策略分派；复用活动已有所有者检查、异步状态与版本存储。活动原分支保留，福利不调用legacyPortraitInputFromCampaignBrief。文案独立Prompt只生成subtitle，title/食品事实锁定；AI输出先解析再确认，亮点中的价格/数量等事实不扩写。依赖01、02。验收：Mock Provider下福利任务从输入到确认/刷新恢复可用；活动旧任务、福利新任务混合保存不丢失；未知scene、伪造templateId、跨场景confirm、越权及重复提交被正确处理。无法解析的存量记录不得在保存其他任务时被静默清除。

- [ ] **04｜食品参数到已确认视觉方案。** 新增T02 Prompt编译器和独立视觉Schema，绑定设计方四个变量，第三步支持查看/修改食品状态、主题色和简短描述。默认确定性编译；显式“AI优化”若实现则只优化受控字段，不生成图片。复用Provider通信层与错误处理，修改seedreamPrompt上层分派，阻止T01构图/风格被附加到T02。依赖03。验收：无花果、榴莲、蛋糕、饮品输入能得到可审阅方案；纯白背景、底部锚定、高度1300–1470和全部禁止项完整；默认最高点540；不能把公司名称、标题副标题、内部事实或用户注入指令作为生成文字发给模型；确认参数未被编译器覆盖。

- [ ] **05｜确认视觉 → 生图适配 → 真正导出。** 复用run-job状态和Provider，按T02选择预检、图片请求尺寸、渲染、校验及独立fallback。记录templateVersion、sceneContractVersion、copyPromptVersion、visualPromptVersion、最终载荷及来源版本。依赖03、04。先用Mock图片服务完成真实Worker/文件链路；原有默认活动背景不得给福利使用。验收：预检失败不收费；点击确认视觉后才调用图片服务；重复确认/重试不重复认领或覆盖版本；失败恢复正确；PNG与预览/下载均使用同一个已校验Artifact；不支持的横版/Banner/长图在API拒绝且不调用模型。

- [ ] **06｜按真实检查结果决定可导出状态。** 新增T02容量/对比度报告，复用文本Range与像素测量基础逻辑，隔离T01区域配置。程序检查画布、字体图片加载、Logo比例与安全区、标题副标题行数、页脚对比度；食品有效高度、畸变、无文字和摄影质感以人工检查记录，状态明确为待审核/通过/失败。依赖05。用户可预览待审核稿，正式下载需程序硬检查与人工视觉审核通过；沿用trial时必须明确试用稿及未检查项，不得显示食品构图已自动通过。验收：食品侵入文字、灰色页脚低对比、字体失败均有可理解处置；未授权自动换白字/遮罩/重新生图。

- [ ] **07｜回归验收与开放员工福利。** 复用现有Vitest、Playwright和npm命令，完成下面矩阵；补充获认可的T02食品兜底资产后再启用正式入口。同步HANDOFF、ARCHITECTURE、CONTRACTS及模板字段矩阵，记录仅支持下午茶和PNG。依赖01–06。交付报告列出文件、执行命令、PNG路径、实际检查/人工检查、未完成项与部署状态。是否发布按用户后续部署指令处理。

## 测试矩阵

| 层级 | 必须覆盖 |
|---|---|
| 契约 | 标题/食品/亮点缺失；视觉可选项默认；副标题事实不新增；未知场景与模板不匹配；福利不要求活动字段 |
| 文案 | 正常短亮点；长亮点需确认精简；折扣/价格/数量不改写；输出非法JSON；超长副标题不截断 |
| Prompt | 设计方所有关键构图/风格/禁止项；四变量完整；T01指导零串入；最长有效参数不超载荷预算；超限请求前报错；主题色与浅背景冲突；食品状态不适用；多食品主次 |
| Provider | 最终9:16尺寸；高分辨率缩放记录；不依赖Prompt文字假装尺寸正确；失败/超时；无食品fallback；不为图片下载失败自动重新付费生图 |
| 任务 | 旧活动、新活动、新福利混合读写；未知/损坏记录不被静默删除；幂等键与owner/scene/template绑定；重复确认、旧草稿确认、失败重试、历史版本不覆盖 |
| UI | 两场景切换/刷新恢复/新建；title不被AI改写；默认参数可理解；不展示无槽字段；其他场景仍不可用；福利只有一种规格 |
| 视觉 | 无花果、榴莲、蛋糕；饮品若纳入首版则核对容器解释；长标题拒绝、长副标题拒绝；食品过小/过高、底部断开、背景复杂、页脚不可读、塑料感/畸变/意外文字 |
| 回归 | T01新多行路径、活动四规格、二维码上传/读取、所有者权限、strict/trial、旧任务恢复均保持正确 |

基本命令：`npm run typecheck`、`npm run lint`、`npm test`、`npm run build`、`npm run render:b2-review`、`npm run render:t01-readability-review`，再运行新增T02 Fixture渲染脚本及相关Playwright场景。实际命令以完成时package.json为准。失败先判断是否来自用户在途修改，记录基线，不通过改弱断言解决。

真实食品生图样张验收在用户同意的调用次数/费用范围内安排；纯排版、状态及Prompt编译测试均不需要付费调用。不能用Mock通过来声称真实食品摄影质量通过。

## 发布前决策与依赖

- T02第一版单行标题/单行副标题为本计划建议；设计若要求多行，先重算文字与食品安全区，不扩大行数直接上线。
- 采用Y=540作为默认食品最高点，处理食品边缘与副标题及页脚的真实对比度冲突。
- 取得适配T02的认可食品fallback资产；示例成品截图不能直接当无字底图。
- 若支持饮品，落实必要容器与no cutlery的解释；原始Prompt保持单独留档。
- 部署前备份业务数据，新福利数据写入后避免回滚到仅支持活动解析的旧版本。关闭福利入口的回退方式应保留新数据读取能力。
