# T01 跨画幅主视觉卡点（待决）

日期：2026-09-10  
状态：待产品与设计决策；未作为已上线能力实现。

## 现象

同一张竖版主视觉用 `object-fit: cover` 投影到四种物料时，竖版与长图可以通过顶部锚定保留标题安全区；横版和 Banner 则需要居中取景。将竖版的顶部锚定直接套到横版，会把球拍主体推到下方并被横版的信息区截断。

这说明问题不是 CSS 裁切参数，而是同一场景在竖向与横向画幅中需要不同、但连续的构图。

## 已确认事实

- 当前图片 Provider 只调用 `/images/generations` 文生图接口；没有将已选图片作为参考图进行编辑、扩图或外延的能力。
- 因此，第二次以相同 Prompt 生成横版，只能得到风格接近的独立抽样，不能保证人物、器材、镜头和场景连续。
- 当前模板已采用保守适配：竖版与长图 `object-position: center top`；横版与 Banner `object-position: center`。
- 当前生成链路是“先生成竖版，再按需用同一素材渲染其他规格”；它不额外调用图片模型，适合低成本预览，但不能保证横版构图最佳。

## 推荐目标方案

将一次活动的主视觉建模为“视觉家族”，而不是一张万能底图：

```text
已确认竖版主视觉
  ├─ 竖版、长图：复用竖版母图
  └─ 用户请求横版预览/物料时：生成横版同场景变体
       ├─ 横版：使用横版母图
       └─ Banner：优先由横版母图裁切；不通过安全区校验时再生成 Banner 变体
```

横版变体必须以已确认竖版图为参考输入，锁定主体、色彩、风格与镜头语义，仅扩展/重构横向画幅；它不是无提示的第二次随机文生图。

## 建议交互

1. 用户确认竖版主视觉后，所有规格先提供“基础适配预览”。
2. 用户点击横版或 Banner 的“生成同场景横版变体”后，创建独立异步任务、明确展示生成成本与等待状态。
3. 成功结果作为该 `visualFamilyId` 下的不可变横版变体保存，可选择或回退到基础裁切预览。
4. Banner 先做确定性裁切与标题安全区/主体可见性校验；失败时才提示生成 Banner 专用变体，避免默认增加第三次图片成本。

## 明日需要决定

1. 选择支持参考图编辑/扩图的图片能力，并确认其可支持的输出比例、分辨率、费用与版权/数据处理边界。
2. 定义“同场景”的验收标准：必须一致的主体、允许变化的背景范围，以及人工选择入口。
3. 确定成本策略：用户显式触发按次计费，或在确认竖版后预生成横版变体。
4. 定义 Banner 的自动裁切阈值；不通过阈值时是否自动生成，还是由用户确认。
5. 扩展 `VisualMaster`/视觉家族契约，记录来源竖版资产、参考图编辑参数、变体关系、模型与用量，保持版本可追溯与可回退。

## 非目标

- 不允许模型直接生成文字、Logo、二维码或任意 HTML/CSS。
- 不把两个独立文生图结果表述为同一场景的连续画面。
- 在图片编辑能力接入前，不将“横版同场景变体”暴露为已可保证的产品承诺。
