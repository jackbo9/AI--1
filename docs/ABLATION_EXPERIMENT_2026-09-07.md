## 结果与实验边界

本轮只接受不改变运行契约的删减：移除一份零引用的不完整 Schema 和一层纯异步转发。保留 Zod 校验、异步调度、幂等认领、历史兼容、四规格输出、Provider、脱敏和发布门。没有变更模板、视觉样式、模型 Prompt、配置默认值、持久化格式或依赖版本。

| 对照 | 改动 | 验证 |
|---|---|---|
| B0 | 原始工作区 | TypeScript、ESLint、75/75 测试通过 |
| A1 | 删除 `posterDocumentJsonSchema` | TypeScript、75/75 测试通过；实际 Provider 仍使用 `posterDocumentSchema.parse` |
| A2 | 在 A1 上删除 `runJob`，创建 API 直接异步调用 `runCopyStage` | 先在原转发层上通过新增的创建／重复提交回归，再切换调用；最终检查见下方 |

`posterDocumentJsonSchema` 无代码消费者，且只描述部分字段；保留它会造成存在第二份完整运行契约的误解。未来供应商确需 JSON Schema 时，应从 Zod 单向生成并验证消费路径，不能恢复手写副本。

`runJob` 只执行 `await runCopyStage(jobId)`，没有调度、事务、状态判断或错误处理。API 仍使用 `void` 异步启动，实际阶段内部原有错误处理保持。新增 API 回归覆盖成功创建仅启动一次、重复幂等提交复用同一任务；原有标题超限不启动任务的测试继续保留。

## 本轮不能删的复杂度

| 候选 | 保留原因／后续条件 |
|---|---|
| Campaign、VisualMaster、Artifact、旧版本迁移 | 四规格已上线，服务依赖来源版本、视觉族与独立 Artifact；旧单竖版消融不再适用。若要收敛双写，需先覆盖历史迁移、四规格追加／失败重试、只换主视觉及下载资格的完整 Worker 集成测试，再设计数据迁移。 |
| Provider、重试、身份、上传所有者校验 | 是现有供应商与安全边界；删除会改变已实现能力。 |
| BrandSpec、Manifest、容量与可读性检查 | 支撑四规格和导出约束；trial／strict 及历史输出资格必须保持。 |
| Prompt Compiler 与本地 fallback | 删除会改变生成质量和失败路径；需同输入盲评与成本证据，编译通过不能替代效果实验。 |

未进行整库死代码删除或领域重构；没有证据的候选不按“行数少”强行合并。收益是少一份重复定义和一层入口跳转，没有声称性能提升。

## 最终验证与回退

最终 `npm run typecheck`、`npm run lint`、`npm test`（20 个文件、76/76 测试）、`npm run build`、`git diff --check` 均通过。生产代码净减 41 行。新增测试最初的 Mock 返回类型不符合已归一化的任务类型，已修正测试数据返回值后完成全部检查，未放宽类型约束。

付费模型、真实飞书端到端和线上部署不在本轮验证范围；未重跑 PNG 视觉回归，模板没有修改，不以本轮结果覆盖既有 Linux 视觉回归缺口。现有测试不能证明所有未测路径，故没有应用需要数据迁移或改变视觉行为的删减。

回退时只反向应用本次代码及文档差异，保留用户文件和之后的改动；不执行整库 reset／clean，不覆盖历史任务。A1 与 A2 彼此独立，可单独恢复。原始实验 [2026-09-04](./ABLATION_EXPERIMENT_2026-09-04.md) 保留，仅增加失效范围说明。
