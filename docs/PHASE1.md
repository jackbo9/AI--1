# Phase 1：含真实生图的飞书端到端最小切片

状态：待执行  
目标：优先跑通完整链路，视觉效果、字段细节和模型质量在后续阶段持续优化。

## 1. 阶段目标

Phase 1 必须完成一条可现场演示的真实链路：

```text
飞书工作台打开应用
  -> 获取并映射飞书用户身份
  -> 填写员工活动信息
  -> 创建异步生成任务
  -> DeepSeek 生成结构化文案
  -> 图片模型生成无文字插画
  -> HTML/CSS 确定性合成
  -> Playwright 输出 PNG
  -> 网页预览与下载
  -> 飞书机器人发送结果卡片
```

本阶段验证的是流程可行性和系统边界，不以最终视觉品质作为通过条件。

## 2. 临时业务假设

会议未确认的内容先使用以下可版本化假设，不阻塞实现：

- 场景：员工活动 `employee_activity`。
- 语言：简体中文 `zh-CN`。
- 输出：竖版 PNG，暂定 `1080 x 1440`。
- 模板：一个固定品牌骨架、一个可变插画槽位。
- 必填字段：活动名称、日期、时间、地点、活动简介。
- 不可改写字段：日期、时间、地点。
- AI 可编辑字段：标题、副标题、摘要、活动亮点。
- 插画风格：现代、简洁、企业内部活动插画。
- 生图失败：回退到默认本地插画或品牌背景。

会议确认后通过新增场景、模板或 Prompt 版本迭代，不覆盖已有生成版本。

## 3. 本阶段范围

### 必须包含

- Next.js + TypeScript 工程和基础质量检查。
- `PosterDocument` Zod Schema 与 JSON Schema。
- 正常、长文本、缺字段三组脱敏 Fixture。
- DeepSeek 文案 Provider 和真实 API 调用。
- 一个真实的图片生成 Provider 和真实 API 调用。
- 图片 Prompt 去敏、负向限制和默认资产降级。
- 一个受控 HTML/CSS 海报模板。
- Playwright PNG 渲染与字体等待。
- 字段完整性、不可改写字段和文本溢出校验。
- 最小异步任务、状态查询、失败与有限重试。
- 飞书网页应用身份接入。
- 结果预览、PNG 下载和机器人完成卡片。
- 模型、Prompt、模板、资产和输出版本记录。

### 暂不包含

- 第二、第三业务场景。
- 多模板、模板自动推荐和自由画布。
- PDF、多尺寸和多语言。
- 高级编辑器及复杂协作审核。
- 多维表格同步。
- 机器人收消息、机器人菜单和卡片内编辑。
- 生产级高并发、Redis/BullMQ 和完整运维后台。
- 正式品牌验收和最终视觉品质调优。

## 4. 图片模型边界

图片模型只生成插画、背景和装饰资产，不生成整张海报。

禁止图片模型生成：

- Logo 或品牌标识。
- 标题、正文、日期、时间和地点。
- 二维码、条形码、字母、数字或水印。

图片 Prompt 只保留活动主题、氛围、季节、人物动作和风格，不发送员工姓名、联系方式、精确地点或其他不必要的内部信息。

示例：

```text
企业员工秋日户外活动插画，温暖、轻松、现代扁平风，
人物进行露营和互动，上方保留干净的标题安全区，
不要文字、字母、数字、Logo、二维码或水印。
```

## 5. 技术实现顺序

### 5.1 工程与契约

- [ ] 初始化 Next.js、TypeScript、ESLint、格式化、Vitest 和 Playwright。
- [ ] 建立 `src/contracts`、`src/templates`、`src/providers`、`src/worker`、`src/integrations/feishu` 和测试目录。
- [ ] 集中校验服务端环境变量，禁止密钥进入客户端 bundle。
- [ ] 定义 `PosterDocument`、`GenerationJob`、`GenerationVersion`、`IllustrationRequest` 和 `GeneratedAsset`。
- [ ] 建立正常、长文本、缺字段三组 Fixture。

验收：typecheck、lint、unit test 和 build 可重复通过。

### 5.2 模型能力探针

- [ ] 验证 DeepSeek API Key、Base URL 和实际可用模型。
- [ ] 验证结构化 JSON 输出、超时和错误响应。
- [ ] 验证图片 API Key、模型、文生图、输出格式和下载方式。
- [ ] 记录两个模型的耗时、错误、版本和可计量用量。
- [ ] 不在日志中输出 API Key 或完整敏感输入。

验收：两种模型均有一次真实成功调用；失败响应可以被稳定解析。

### 5.3 确定性海报生成

- [ ] 实现一个员工活动模板及模板元数据。
- [ ] Logo、正文、时间和地点由 HTML/CSS 绘制。
- [ ] 图片模型结果只能进入模板声明的插画槽位。
- [ ] 等待字体和图片资源完成加载后截图。
- [ ] 输出固定尺寸 PNG。
- [ ] 检查必填字段、不可改写字段、Logo 比例和文本溢出。
- [ ] 建立首张视觉回归基线。
- [ ] 图片 API 失败时使用默认资产重新渲染。

验收：真实生成插画可以合成到海报；失败降级也能生成合规基础海报。

### 5.4 最小异步任务

- [ ] `POST /api/jobs` 创建任务并返回 `202 Accepted`。
- [ ] Worker 执行文案、生图、渲染、校验和结果保存。
- [ ] `GET /api/jobs/:jobId` 返回步骤、状态、错误和预览地址。
- [ ] 实现幂等键、有限重试和不可变生成版本。
- [ ] 本地保存 PNG；存储接口保留替换能力。

最小状态流：

```text
QUEUED
  -> VALIDATING_INPUT
  -> GENERATING_COPY
  -> GENERATING_ASSET
  -> RENDERING
  -> VALIDATING_OUTPUT
  -> READY_FOR_REVIEW
  -> EXPORTED
```

验收：刷新页面不丢任务；重复提交不产生重复收费调用；失败任务可安全重试。

### 5.5 最小产品界面

- [ ] 员工活动输入表单。
- [ ] 任务生成状态页。
- [ ] 结果预览和 PNG 下载页。
- [ ] 支持修改允许编辑的文案并创建新版本。
- [ ] 支持只重新生成插画，不改写文案。

验收：用户不需要编写 Prompt 即可完成一次生成。

### 5.6 飞书接入

- [ ] 从飞书工作台打开网页应用。
- [ ] 获取飞书用户稳定标识并映射到内部 `userId`，不以姓名作为主键。
- [ ] 任务完成后机器人向创建者发送结果卡片。
- [ ] 卡片包含任务状态、摘要和“查看海报”链接。
- [ ] 飞书通知失败只记录并重试，不改变核心任务完成状态。

首版卡片按钮只跳转结果页面，不处理卡片动作回调；首版机器人不接收用户消息。

## 6. 本地运行与飞书联调

应用、数据库、Worker、Playwright 和生成文件均可先在本机运行。飞书工作台页面和登录回调需要飞书能够访问的 HTTPS 地址，因此采用：

```text
飞书
  -> 公司允许的 HTTPS 测试域名或安全开发隧道
  -> 本机 Next.js/API
  -> 本机 Worker、数据库和输出目录
```

未经公司确认，不使用公共隧道传输真实内部数据。测试输入必须脱敏。

## 7. 用户侧飞书操作

### 7.1 创建测试应用

- [ ] 在飞书开放平台创建“企业自建应用”。
- [ ] 建议名称：`九号行政智绘引擎（测试）`。
- [ ] 添加“网页应用”能力。
- [ ] 添加“机器人”能力。
- [ ] 获取 App ID 和 App Secret。
- [ ] App Secret 只写入本机 `.env.local` 或公司 Secret 系统，不通过聊天、文档或 Git 传递。

### 7.2 申请最小权限

- [ ] 登录用户基本身份权限。
- [ ] 以应用身份发送消息的权限。
- [ ] 如果结果卡片直接显示 PNG，再申请机器人上传图片所需权限。

暂不申请全量通讯录、群管理、多维表格、云文档、日历或审批权限。具体权限标识在代码确定实际 API 后再按飞书后台提示补充。

### 7.3 配置测试地址

获得 HTTPS 地址后配置：

```text
桌面端主页：https://测试域名/
移动端主页：https://测试域名/
登录重定向：https://测试域名/api/auth/feishu/callback
```

- [ ] 向 IT 确认是否允许开发隧道或是否提供测试域名。
- [ ] 确认是否需要 IP 白名单、备案域名或公司测试服务器。
- [ ] 将应用可用范围限制在 5–10 名测试人员。
- [ ] 创建测试版本并提交管理员审批。

### 7.4 首版不配置的飞书能力

- 机器人接收消息。
- 机器人菜单。
- 卡片交互回调。
- 多维表格同步。
- 全员发布。

这些能力不影响 Phase 1 的工作台进入、网页生成和机器人主动通知闭环。

## 8. 需要用户提供的配置

所有密钥由用户在本机或公司 Secret 系统中填写：

```env
# Feishu
FEISHU_APP_ID=
FEISHU_APP_SECRET=
FEISHU_REDIRECT_URI=https://测试域名/api/auth/feishu/callback

# DeepSeek
LLM_PROVIDER=deepseek
LLM_BASE_URL=https://api.deepseek.com
LLM_API_KEY=
LLM_MODEL=

# Image generation
IMAGE_PROVIDER=
IMAGE_BASE_URL=
IMAGE_API_KEY=
IMAGE_MODEL=
```

图片供应商还需确认：服务端 API、输出格式、尺寸、费用、频率限制、数据保留政策、商业使用条件和中国大陆网络可用性。

## 11. Phase 1 结束后再处理

Phase 1 的运行结果用于暴露并排序后续缺口：

- 模型与 Prompt 质量。
- 正式字段协议。
- 品牌模板和插画风格。
- 长文本与多语言。
- 更多场景和尺寸。
- 生产数据库、对象存储、监控和安全评审。

后续优化不得改变 Phase 1 的核心职责边界：AI 生成内容和可变视觉资产，代码负责确定性排版、不可改写字段、Logo、二维码和最终输出。
