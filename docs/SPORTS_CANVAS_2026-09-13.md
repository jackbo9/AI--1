# 体育主视觉坐标修正与真实验收（2026-09-13）

2026-09-13 第一版锁定：多尺寸已回退为同一母图自动裁切排版，选图后不调用图片模型或主体识别。最新行为、兼容与实际验收以[裁切锁定记录](RELEASE_CROP_2026-09-13.md)为准；下方独立生成/扩图相关内容仅为历史记录。

本轮由用户采纳四项建议授权：统一四规格坐标、替换冲突约束、验证并实现按规格生成、同一篮球场景真实对照。第二步“返回上一步”已移除；顶部流程仍可返回文案。

## 实现

- sports-canvas.ts 为完整尺寸、核心区域、标题区、底部背景边界和请求尺寸的共享配置。Prompt 同时写像素坐标及等价百分比；禁止旧 68%–78% / 48%–58% 中心与向下延展指令。摄影语言只选择适合的少量项，色彩是倾向。
- 新确认描述保存 canvasTarget；两张主视觉都按竖版完整画布生成，以视角区分。确认选图后，其他所选规格冻结同一描述及方向快照，分别生成完整背景，状态与失败相互独立。保留语义方向，不保证不同尺寸复现同一球网几何或同一摄影画面。
- 实测网关返回 400，明确宽高必须为 16 的倍数。使用 1088×1920、1920×1088、2240×960、1088×3008 请求；右侧/底部仅增加背景出血，校验返回原始尺寸后提取左上目标窗口，不缩放、不居中裁切主体。保留 native 原文件，成品分别是 1080×1920、1920×1080、2227×950、1080×3000。
- 新竖版背景按完整 1080×1920 显示，信息面板独立覆盖；新长图按 1080×3000 显示并固定成品高度。旧任务无 canvasTarget 时保留旧素材与排版方式。新模式的完整画布不会再次塞入短的主视觉窗口。
- 追加规格 Artifact 保存 sourceBrief、actualPrompt、模型来源和独立图片。重复请求复用认领；图片成功但模板失败时，重试复用图片，避免再次收费。新图片请求不自动重试；前端提供重试当前尺寸。
- 第二步竖版预览遵守完整画布映射。其他规格在正式生成前仍为草稿预览；不等同于独立生成后的成品。

## 实际检查与限制

- 类型检查、Lint、生产构建通过。
- 全量 35 文件 / 139 项测试通过；之后新增的“冻结尺寸描述、并发只认领一次、渲染失败复用图片”测试和坐标相关测试通过。
- 8 项浏览器回归通过，涵盖顶部返回、描述阶段、四档宽度、多尺寸自动预览与连续缩放。浏览器测试未调用付费模型。
- 同一篮球场景完成四规格真实 gpt-image-2 生图，约每张 29–44 秒（本次样本，不是未来等待承诺）。完成正式渲染与 PNG/JPG 尺寸核验。
- 原图人工观察：竖版主体落在右侧核心区，但底部地面反光偏强；横版主体在右上、底部无主要器材；Banner 左侧环境结构/灯光偏繁杂；长图初版靠近底部禁区，追加等价百分比和上部三分之一说明后，末版主体完整回到上方。
- 不能将这些观察表述为四张全部符合品牌规则。尚无自动主体/高光语义识别检查，字体/尺寸/对比度通过不等于构图通过；需要设计师审查样张。
- 跨尺寸保持描述与设计方向，不是图像参考编辑或扩图；本轮未实现多尺寸严格同图一致性。
- 历史像素截图基线此前在原始提交也失败，本轮没有更新该基线或宣称通过。
- 新模式已加载本地，未推送、未提交 PR、未部署云端。
