## 3. 将交接要求转成字段契约

| 字段 | 竖版 | 横版 | Banner | 赛后长图 |
|---|---|---|---|---|
| 活动主题，作为生成输入 | 是 | 是 | 是 | 是 |
| 宣言标题 / 主标题 / 副标题 | 是 | 是 | 是 | 是 |
| 日期、时间、地点 | 是 | 是 | 否 | 是 |
| 参与对象、活动规则、二维码 | 是 | 是 | 否 | 否 |
| 入围名单 | 否 | 否 | 否 | 是 |
| 城市，从地点派生 | 否 | 否 | 否 | 是 |
| 活动照片 | 否 | 否 | 否 | 本轮占位 |

- 默认竖版；竖版、横版、Banner 可多选，赛后长图与前三者互斥，至少选择一个。
- 01 显示所选模板字段的并集；02 编辑区与当前预览 Tab 的字段投影一致。共同标题及竖横版事实共用同一份值。
- 切换模板保留隐藏草稿，但请求按当前模板投影；隐藏数据不能误传给模型，也不能无意出现在预览。
- “上场指南 / 先看这里 / 一起上场 / 扫码报名”等固定标签不可编辑。城市由地点自动更新，不创建第二个可独立修改的城市真源。
- 新流程去掉补充说明、报名截止、联系人、奖品和第二场次入口；旧任务仍能读取，不能在刷新或迁移时把旧数据删掉。
- 将活动主题与 AI 主标题分离；宣言标题进入明确的草稿类型和响应，不用摘要字段冒充。旧任务缺失时使用明确兼容值。

## 4. 文档中的范围冲突及处理

| 交接要求 | 当前约束 | 建议处理 |
|---|---|---|
| 仅改前端，Banner 单独选择且不用事实 | 创建任务需要场次、参与对象，并执行 T01 预检 | 前端可先完整演示；真实提交需要模板感知的输入契约，禁止填假日期/对象绕过校验 |
| 02 修改日期、地点、对象、二维码 | 确认接口不接收这些值，后续使用确认快照 | 同步扩展确认接口和事实修订规则；用户修改形成新快照，AI 仍不得改写事实 |
| 赛后长图包含入围名单 | 现有长图格式不等于赛后业务模板 | 独立模板契约与草稿类型；不要只凭长图尺寸复用旧模板身份 |
| AI 生成宣言标题且刷新恢复 | 当前草稿、Provider、响应和恢复链路未完整支持 | 必须跨类型、模型结构化输出、存储、轮询、Fixture 一起做 |
| 不改 PNG、不改 03/04，同时四模板可预览 | 新预览字段与正式输出可能不一致 | 本轮将新增版式标为预览能力；不能宣称已获得对应成品，也不能默默下载另一种模板 |
| 保留刷新恢复 | 当前未确认编辑与模板选择不是完整持久化草稿 | 增加按用户/任务隔离的草稿恢复；旧轮询结果不能覆盖新编辑 |

推荐分成“01/02 可验收改版”与“新模板正式出图接入”两个交付。第一阶段可完成全部前端交互和必要的草稿接口，但 Banner-only、赛后长图的后续出图不能伪装成旧竖版任务。若坚持 03/04 与渲染完全零变更，这两条路径止于明确标注的草稿预览；若要求它们一路下载成品，则必须扩展第二阶段范围。已有受支持的竖版流程继续贯通。
