## 4. 新 HTML 带来的明确价值

来源：`表单格式/employee-activity-poster-demo.html`。

- 界面组织：顶部四步流程，左侧场景导航，中间当前阶段工作区，右侧持续预览。
- 表单组织：必填事实与可选内容分开，二维码按需展开。
- 视觉语言：浅色工作台、白色表单区、MiSans、黑色主按钮、行政黄步骤/选中反馈、红色场景强调。
- 体验方向：用户先确认内容，再处理视觉，再查看质量结果和导出。

这些可以成为产品 UI 升级的依据。产品界面设计系统与海报输出模板需分别管理：界面卡片、间距和控件样式，不会自动改变已锁定的 T01 海报几何与品牌规则。

HTML 当前是可交互本地原型：文案优化由字符串拼接模拟，生图按钮用定时提示模拟，保存草稿仅显示提示，历史入口为空态。四尺寸预览由本地 SVG 构造，PNG 使用浏览器 Canvas 导出，未接项目 API。二维码 URL 生成和本地图片读取已有前端实现，但尚无后端上传契约。

### 今日调整：轻处理、保留生成图、暴露真实问题

用户明确接受试用阶段出现文字与背景对比度不足，认为这比整张换成默认背景更有利于判断优化方向。本次决策覆盖此前“对比度失败必须换底图或阻断”的试用策略；不把该变化描述成已通过原有质量标准。

建议的最小实现：

- 图片生成成功：保留原生成背景，不再仅因对比度不足自动换掉整图。
- 限制局部遮罩强度；先以最高 0.12 作为待实图核验的起点，避免继续加重处理。
- 对比度继续测量并保存真实结果；不足时显示“文字与背景对比度待优化”，作为试用警告呈现。
- 允许查看结果，并提供明确的“下载试用稿”路径；不得为实现下载把失败测量伪写成通过。输出可用性与视觉质量需分别表达。
- 图片服务确实失败时，明确提示生成失败，保留现有故障兜底；不要混淆“没有生出图”和“图已生成但文字难读”。
- 事实一致性、字体/Logo 加载、重要内容溢出、二维码有效性和身份权限仍执行原有检查。
- 改动以显式试用策略落地，保留后续恢复严格发布策略的路径；同步 HANDOFF、ARCHITECTURE、CONTRACTS 中相关说明。

后续再按以下方向实验：

- 保留同一个 T01 信息结构，设计少量受控对比度变体；浅底深字、深底浅字、上下分区只是候选，尚未决定全部实现。
- 生图前把所选变体与对应安全区送入 Prompt，使背景生成与文字方案一致。
- 渲染后继续校验，使用经过视觉验收的轻处理；不把提高最大遮罩强度作为默认优化路径。
- 使用同一组活动输入，比较画面质量、文字可读性、遮罩强度、整图替换次数、耗时和调用成本。

Prompt 可以降低问题出现概率，不能保证每张图达标。变体也必须覆盖局部明暗混合的背景；只增加整张黑字/白字两套并不自动解决局部冲突。当前不应只凭一次样张宣布问题解决，也不需要今天先扩写一套复杂自适应引擎。
