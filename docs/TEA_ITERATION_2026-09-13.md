# 员工福利 · 下午茶接入

开发分支：`codex/afternoon-tea-20260913`，起点 `ff439db`。实施前只读确认上一轮 PR #4 仍 OPEN、未合并；本轮不改变该 PR 或部署云端。

## 行为

- 点击现有员工福利侧栏直接进入下午茶，共用三步工作台。体育与下午茶草稿各自保留；`?scene=employee-afternoon-tea` 为新建入口，`?job=…` 可恢复已创建下午茶任务。
- 一个自然语言输入，AI 整理后展开食品、7 字主标题、24 字副标题；同次整理准备画面描述，第二步默认折叠。食品、时间、地点的模型提取必须是原文连续片段，非原文结果置空；食品可人工补充。
- 默认两张食品摄影方案、主动选图、失败项单独重试。改动已确认字段会创建新任务版本并关联 `previousJobId`，原任务和图片保留。字段比较不依赖 JSON 键顺序。
- 无图片上传/图生图、多尺寸、时间地点展示、二维码或历史列表。试用模式不调用模型并明确显示固定文案/演示图片，不能正式下载。
- 双 Logo 和 MiSans 来自探索版原资产；正式模板为受控 HTML 内 SVG 布局，由 Playwright 截图，浏览器预览复用同一布局函数。输出 1080×1920，图片 cover、水平居中、底部对齐。标题基线 416、副标题基线 497；字体 120/28px；最大文本宽度 936px。

## 接口、数据与兼容

- `POST /api/tea/extract` 接收 `{brief}`，返回 `{fields,missing}`。使用现有身份和文字模型 Provider；失败不生成伪造成功内容。前端丢弃请求期间人工编辑后返回的旧结果。
- `POST /api/jobs` 新增 `{scene:"employee-afternoon-tea",fields,idempotencyKey,previousJobId?}`；返回下午茶任务。旧体育请求与响应保持。
- 查询仍使用 `/api/jobs/:id`。下午茶动作复用 `confirm-visual`、`visual-options/select`、`visual-options/confirm`、`visual-options/retry` 路由，携带 `sourceVersionId`、`idempotencyKey`；生成增加 `description`，其他动作增加 `optionId`。后端逐任务原子认领，重复 key 不再启动模型。
- JSON 真源沿用 `data/jobs.json` 和单进程串行原子写入。按场景分别校验，体育更新保留茶任务，茶更新保留体育任务；文件损坏停止写入而非覆盖为空数组。重启恢复区分场景，未完成茶方案可重试，成功项保留。
- 图片 Provider 抽出接收服务端受控 Prompt 的请求层。食品规则不经过体育 Prompt 编译器；食品请求 1024×1536、沿用当前质量档位，无自动重试收费请求，无体育 fallback 冒充食品成功。原图和轻量 JPEG 私有保存，所有 `/api/files` 请求继续校验归属。
- 正式输出记录来源版本、方案、模板版本和对比度。黑字区域背景第 10 百分位对比度阈值为标题 3、副标题 4.5；strict 不通过不能下载，trial 允许并保留警告。该像素检查不能判断食品语义或每个字形的全部细节。
